# AGENTS.md — Japan Travel Plan

Guide for LLM agents working in this repository. Read this before editing data, scripts, or the map UI. User-facing overview lives in `README.md`.

## What this project is

A static browser map of ~2,280 places to visit in Japan. Data comes mostly from a friend's Google My Maps KML exports (9 regions + Tokyo), plus a hand-maintained **Tokusatsu** list owned by the repo author.

- **Live site:** [cobalto.dev/japantravelplan](https://cobalto.dev/japantravelplan)
- **Title:** `Japan Travel Plan · Cobalto.dev`
- **Stack:** Vanilla JS + Leaflet + MarkerCluster (CDN + SRI). No npm/build toolchain. OpenStreetMap tiles (no API key).
- **Runtime:** Root `index.html` is self-contained (place data inlined). Needs internet for CDN libs and map tiles.

| KML file | App group name |

## Build commands

Requires Python 3 and `pykakasi`:

```bash
pip3 install pykakasi
```

### Regenerate the map app (most common)

```bash
python3 app/build-places.py
```

- Reads all `KML/*.kml` + `Locations/Tokusatsu.md` + `app/name_overrides.json`
- **Does not** call the network (no GSI/Nominatim/Google).

### Optional name/geotag enrich (never required for rebuild)

`python3 app/enrich_places.py` is **optional**. It reverse-geocodes the dirty subset (generic / Portuguese-looking names) via GSI + Nominatim with a polite ≥1 req/s rate limit and User-Agent `japantravelplan/cobalto.dev`, then writes git-trackable `app/enrich_cache.json` and human-review `app/enrich-proposals.md`. It does **not** rewrite `name_overrides.json` or move coordinates — copy accepted lines by hand. A normal `build-places.py` rebuild stays offline and does not need the network or this cache.
- Writes root `index.html` (compact JSON) and `app/places.js` (pretty reference)
- Embeds `window.PLACES_DATA` into `app/index.shell.html` at `PLACES_DATA_PLACEHOLDER`
- Prints a build report (dupes dropped, tokusatsu merged vs only, generic/Portuguese names)

### Regenerate region markdown files from KML

```bash
python3 app/build-locations.py
```

- Writes `Locations/{Group}.md` for each KML file
- **Deletes** all `Locations/*.md` except `Tokusatsu.md`
- Does **not** update `index.html` — run `build-places.py` after if the map should change

### Typical workflow after KML changes

```bash
python3 app/build-locations.py && python3 app/build-places.py
```

### Tokusatsu-only changes

If you only edited `Locations/Tokusatsu.md`:

```bash
python3 app/build-places.py
```

`build-locations.py` does not touch Tokusatsu.

## Name normalization (`app/normalize_names.py`)

Used by both build scripts. Do not duplicate this logic elsewhere.

### Group names — `normalize_group_name()`

1. Strip `[N]` prefix (e.g. `[1] Kanto - …` → `Kanto - …`)
2. Strip trailing ` - {Japanese}` suffix
3. Title-case all-uppercase alpha names (`TOKYO` → `Tokyo`)

### Place names — `normalize_place_name()`

**Display format when Japanese is present:** `{Romaji or Latin label} ({Japanese original})`

**Latin-only names** (no Japanese script): keep as-is (e.g. Portuguese labels like `Torre de Tóquio`).

#### Mixed KML names: regionalized Latin + Japanese

Friend's KML sometimes bundles a **regionalized label** (Portuguese, etc.) with the real Japanese name:

```
Salão Showa 美遊ヘアスタジオ   (KML raw name)
→ Miyu Heasutajio (美遊ヘアスタジオ)   (display)
```

Rules:

1. Extract Japanese-only substring via `_extract_japanese_original()`
2. If Latin **before** Japanese is **regionalized** (accented chars like `ã`, `õ`, or Latin that does not match romaji of the Japanese), **discard** the Latin prefix and build display name from Japanese only
3. If Latin before Japanese **matches** transliteration (e.g. `Hozenji Yokocho 法善寺横丁`, `Tokyo Tower 東京タワー`), keep the Latin as the romaji part

#### Other patterns (keep existing Latin when appropriate)

| KML pattern | Display example |
|-------------|-----------------|
| `ハコビバ（HAKOVIVA）` | `HAKOVIVA (ハコビバ)` |
| `honu.cafe (ホヌカフェ)` | `honu.cafe (ホヌカフェ)` |
| `浅草寺` (Japanese only) | `Sensouji (浅草寺)` |

#### Edge cases handled

- Empty `()` from Latin-only parentheticals (e.g. `ハコビバ(HAKOVIVA)` extraction) are stripped
- Fullwidth punctuation normalized to halfwidth before processing

## Google Maps URLs

**Critical:** Display name and URL query name are **different** on purpose.

### `google_maps_url(source_name, lat, lng)`

```text
https://www.google.com/maps/search/?api=1&query={encoded_query},{lat},{lng}
```

### Query name — `maps_query_name()` / `japanese_original_name()`

| Source name type | URL query uses |
|------------------|----------------|
| Contains Japanese | **Japanese original only** (regionalized Latin stripped) |
| Latin only | Full original name |

**Why:** Google Maps regionalization breaks links when the KML bundles Portuguese + Japanese. Example:

```
KML:  Salão Showa 美遊ヘアスタジオ
URL:  …query=美遊ヘアスタジオ,35.7227518,139.6889626
```

### Where URLs appear

- `Locations/*.md` — Google Maps column (from KML via `build-locations.py`; tables also have an Area column from KML folders)
- `index.html` / map popups — each place has a `url` field (from `build-places.py`)
- `Locations/Tokusatsu.md` — **manual**; `build-places.py` reads column 3 if it starts with `http`, otherwise generates `name,lat,lng`

### Tokusatsu URL format

Must use **name + geolocation** (not coordinates-only):

```text
https://www.google.com/maps/search/?api=1&query=Funado+Bridge+%2F+Funado+Riverside+Park+%28Itabashi%29,35.791359,139.672992
```

Coordinates column format: `lng,lat,0` (KML order).

## `Locations/Tokusatsu.md` — special rules

- **Not generated from KML.** Do not run bulk regeneration over it.
- Hand-curated list with section headers (`**TOKYO — Ultraman**`, etc.) — headers set `tokusatsuArea`; they are not places
- **Not a map group.** Matching coords (or name + ≤100 m) merge onto the existing KML pin with `tokusatsu: true`. Unmatched rows are filed under the section’s region (see `TOKUSATSU_SECTION_GROUP` in `parse_places.py`)
- For one-off Tokusatsu URL fixes, edit the MD; `build-places.py` keeps column-3 `http` links on unmatched rows
- Places are English/Latin names (no Japanese normalization needed for URLs)

## Map UI (`app/index.shell.html`)

**Always edit the shell, then run `build-places.py`.** Do not hand-edit the JS logic in `index.html` unless doing a one-off Tokusatsu hotfix.

### Data shape (`window.PLACES_DATA`)

```json
{
  "order": ["Tokyo", "Kanto", "Chubu", "Kansai", "Chugoku", "Shikoku", "Kyushu", "Tohoku", "Hokkaido"],
  "bounds": { "Tokyo": [minLat, minLng, maxLat, maxLng] },
  "groups": {
    "Tokyo": [
      {
        "id": "…",
        "name": "…",
        "lat": 35.0,
        "lng": 139.0,
        "url": "https://…",
        "overviewUrl": "https://www.google.com/search?q=…",
        "q": "search haystack",
        "area": "Minato",
        "tokusatsu": true,
        "tokusatsuArea": "TOKYO — Ultraman"
      }
    ]
  }
}
```

`groups[name]` is still a **flat array of places**. `area` / `q` / `id` / `tokusatsu*` are extra fields; omit `tokusatsu` when false. The UI nests **Region → Area → Place** from `place.area` (places with no area list directly under the region). Do not re-add Tokusatsu as a 10th region — it is a chip filter on `tokusatsu: true`.

### Region checkboxes ("Show on map")

Each source group has a checkbox filter. Rules:

| State | Map pins | Sidebar list header | List expand/collapse |
|-------|----------|---------------------|----------------------|
| **Checked** | Visible | Normal styling | User can click header to expand/collapse |
| **Unchecked** | **Hidden** (removed from cluster) | Muted + "· hidden on map", `cursor: default` | **Forced collapsed, cannot expand** |

**Important behaviors:**

- Unchecking a region **does not** auto re-enable it when clicking pins or list items — disabled regions stay off until the checkbox is checked again
- Pins from unchecked regions are not on the map, so users should never interact with them
- `showPlace()` returns immediately if `!groupEnabled[gid]`
- Use `document.getElementById("filter-g" + gid)` for checkboxes — **not** `$("#filter-g" + gid)` (jQuery misparses `#filter-g0`)

### Nested list (Region → Area → Place)

- Cold load renders **group headers only** (~9). Do not prebuild place buttons or area rows.
- Expanding a **group** renders **area headers** from `place.area` (counts on the header). Places with no area list directly under the region.
- Expanding an **area** renders that area's place rows. Destroy on collapse is fine.
- One delegated click handler on `#place-list` for group titles, area titles, and place rows.
- Sticky group headers on desktop only (skip if it fights mobile).

### Search

- Needle: accent-stripped once per keystroke; match with `place.q.indexOf(needle)`
- Filters the **sidebar list and the map** (debounced ~150ms). Toggle a filtered subset of already-built markers — **never** `cluster.clearLayers()` + rebuild, and never recreate markers per keystroke
- Scoped to **currently checked** regions **and** the Tokusatsu chip (if on)
- When search text is non-empty: matching enabled groups and matching areas auto-expand; render only matching places; non-matching groups hidden (`group-no-match`); `fitBounds` on match lat/lng; show **N matches** near the search row
- When search is empty: does **not** force-collapse enabled groups/areas (user collapse state preserved); restore enabled-group markers (still respecting the Tokusatsu chip)
- The native search input **x** only clears the query (does not reset regions or the Tokusatsu chip)
- **Reset** button: clears search, checks all regions, turns the Tokusatsu chip off, collapses all groups/areas, clears `#p` / persisted q+tok+place, restores full enabled-group markers (keeps theme)

### Tokusatsu chip

- A chip/checkbox (`#filter-tokusatsu`), **not** a 10th region in `order`
- When on: only `tokusatsu: true` places in the list **and** on the map (still respecting enabled geographic regions)
- Tagged list rows get a small **Tokusatsu** badge — not a second pin
- Godzilla Head (etc.) stays one marker; the tag lives on the surviving geographic record

### Map popups

Each pin popup shows:

1. Place name (bold)
2. Group · area (small)
3. **Maps** button — opens `p.url` (Google Maps) in a new tab
4. **Overview** button — opens `p.overviewUrl` (Google Search) in a new tab
5. **Directions** — Google `/maps/dir/?api=1&destination=…` from place coords/name
6. **Apple Maps** — only when the UA looks like iPhone/iPad
7. **Copy link** — copies the current page URL with `#p={stable place.id}`

Overview URL query (build time): `{japanese if present else source name}, {region}, Japan` via `overview_search_query()` / `google_overview_url()` in `normalize_names.py`.

### Themes + tiles

Light / Dim / Dark affect **sidebar UI only**. The map always stays on the light look: free OpenStreetMap tiles, light cluster numbers, light Leaflet controls/popups. Do **not** swap to CARTO/dark tile providers (credentials) or let `html.dim`/`html.dark` restyle `#map` chrome (cluster counts inherit `color` from the page otherwise). Initial theme: `localStorage.theme` if set, else `prefers-color-scheme` (dark → dark, otherwise light). Do not override an explicit saved theme.

### Locate me

Leaflet control (top-left) calls `map.locate`. On success, a small red circle marks the user; on deny/unavailable, a brief status toast — **no alert() spam**. Does not rebuild markers or break `showPlace` / cluster zoom.

### Fit visible

After region toggles (and after search/Tokusatsu filter settles), fit the map:

- **No search/Tokusatsu filter:** union of **precomputed** `data.bounds[groupName]` for enabled groups (never scan ~2250 places).
- **Skip jumpy Japan-wide fit** when 8–9 groups are enabled, or the union lat/lng span is country-scale. Still fit when 1–3 regions are on.
- **Filter active (search or Tokusatsu):** always fit to the current match lat/lng set.

### Region tint colors

Each geographic group uses a distinct `L.circleMarker` fill (9 colors chosen for OSM). Style is applied **once** when markers are created — do **not** recreate all markers on theme change (theme only restyles the sidebar). Tokusatsu is a list badge + chip filter, **not** a 10th marker color.

### Keyboard

| Key | Action |
|-----|--------|
| `/` | Focus search (ignored while typing in an input/textarea/select) |
| `Escape` | Blur search when search is focused |
| `↑` / `↓` | Move focus among **visible** list controls (group/area headers + place rows) |
| `Enter` | Open focused place pin, or toggle focused group/area header; if nothing list-focused, open the active pin |

Do not steal other keys from the search box.

### a11y

- Group and area headers are `<button type="button" aria-expanded="…">` (delegated clicks on `#place-list` still work).
- List/Map tabs use `aria-pressed`.
- Tokusatsu chip and region checkboxes have accessible names (`aria-label` / wrapping `<label>`).
- `:focus-visible` rings on interactive controls.

### CDN SRI

Pin Leaflet 1.9.4 and MarkerCluster 1.5.3 from unpkg with real `sha384-…` `integrity` attributes and `crossorigin=""`. Recompute hashes if the CDN URL/version changes — **never invent hashes**. OSM tile URLs do not need SRI.

### Persist + URL

| Key / param | Meaning |
|-------------|---------|
| `localStorage.theme` | light / dim / dark |
| `localStorage` `jtp.groups` | JSON array of enabled group names |
| `jtp.q` / `jtp.tokusatsu` / `jtp.place` | search text, `"1"`/`"0"`, last stable `place.id` |
| URL `?g=Tokyo,Kansai&q=…&t=1` | enabled groups, search, Tokusatsu chip |
| URL `#p={stable id}` | selected place |

Rules:

- On first load, **URL wins** over localStorage when any of `g`/`q`/`t`/`#p` is present.
- Changing filters/search updates the URL via `history.replaceState` (no full reload).
- Opening `#p=id` selects that place; if its group is off, **enable that group** (shared-link exception — normally checkboxes are the only way to re-enable a region).
- Persist the stable `place.id` hash, never the ephemeral runtime `pid`.
- **Reset** clears search, Tokusatsu, hash, and persisted q/tok/place (re-enables all groups, collapses lists). **Keeps theme.** Native search **x** still only clears the query.

### Groups start collapsed

All region lists begin collapsed on load (unless a search expands matches).

### Mobile / short-height layout

Use List|Map tabs when **`max-width: 767px` OR `max-height: 500px`** (landscape phones), not width-only.

- Default view: **List**; selecting a place switches to **Map** and zooms to the pin
- Keep `#place-list` scroll position when Map → List
- On Map with a selection: **selected-place bar** (name, area/group, Maps, Overview, Directions, back to List). Companion to the Leaflet popup — do not replace the popup
- Map calls `invalidateSize()` on tab switch, orientation change, and resize
- Touch targets enlarged (44px min on controls); search input `font-size: 16px` to avoid iOS zoom
- Wide + tall desktop: tabs/bar hidden, sidebar + map always visible; edit `app/index.shell.html` only

## Pitfalls for agents

1. **Do not edit `index.html` UI logic for permanent changes** — edit `app/index.shell.html` and rebuild.
2. **Do not regenerate `Locations/Tokusatsu.md`** with `build-locations.py` — it is intentionally excluded.
3. **Do not use full KML name in Google Maps URLs** when Japanese is present — use `maps_query_name()` logic.
4. **Do not treat regionalized Portuguese labels as romaji** — strip them for display and URLs.
5. **Do not re-enable unchecked regions from map/list clicks** — checkbox is the only way to turn a region back on (**exception:** shared `#p=` / deep link may enable the place’s group so the pin is visible).
6. **Do not force-collapse enabled groups on checkbox toggle** — only collapse + lock **disabled** groups.
7. **Coordinates:** KML and MD use `lng,lat,0`; place JSON uses separate `lat` / `lng` floats.
8. **Do not call geocoders from `build-places.py` or the browser.** Overrides are the name source of truth; optional `enrich_places.py` writes a committed cache + proposals only.
9. **Do not add Tokusatsu back as a 10th `order` group** — it is a tag/filter. Duplicate pins with regional KML must merge.
10. **KML folders become `area`.** Generic names (`1`, `Hospedagem N`, `Mountain`) display as `{area} · {name}`.
11. **Keep `README.md` in sync** with user-visible behavior; this file holds implementation detail agents need.
12. **Search is list + map.** Do not treat search as list-only. Do not `clearLayers()` the cluster to apply a query.
13. **Do not recreate markers on theme change** — region tint is fixed at creation; theme only restyles the sidebar (basemap stays OSM).
14. **Do not invent CDN SRI hashes** — fetch the pinned unpkg bytes and compute sha384, or omit integrity with a note.
15. **A2 enrich is optional.** Never geocode in the browser; never auto-apply `enrich-proposals.md` to `name_overrides.json` without human accept.
